---
title: "HQ Management API"
description: "Loopback HTTP API for monitoring and administering a running DashSquad HQ."
---

The HQ Management API lets you monitor and control the HQ programmatically. It's the same API
Desktop uses to deploy agents, connect messaging apps, store credentials, and install plugins.
It binds to `127.0.0.1` on port `9300` by default. Change the port with `--management-port`.

This page documents the administrative routes. Phones, tablets, and the web app never receive
administrative access. They use the versioned `/mobile/v1` namespace instead, documented in the
[HQ Mobile API](/api-hq-mobile).

## Overview

The HQ runs up to three HTTP listeners:

| Listener | Default address | Serves |
|----------|-----------------|--------|
| Management | `http://127.0.0.1:9300` | Every route on this page, plus `/mobile/v1` |
| Channel server | `http://127.0.0.1:9200` | The `/ws/chat` WebSocket. See [HQ Chat WebSocket](/api-hq-chat-websocket) |
| Mobile LAN | `https://0.0.0.0:9400` | Only `/mobile/v1`, `/mobile/v1/*`, and `/ws/chat`. Runs only when LAN TLS is configured |

The mobile LAN listener forwards each `/mobile/v1` request to the management listener's own
handlers in the same process. A request for any other path, including every route on this page,
never reaches them. The hosted relay works the same way: it forwards only `/mobile/v1` traffic,
which the HQ replays against its management listener. Administrative routes are therefore
reachable only from the HQ machine itself.

Each route below is marked **Loopback only** or **Also under `/mobile/v1`**. A route that is also
under `/mobile/v1` has the same handler at `/mobile/v1` plus the path, authenticated with the mobile
bearer. Some mobile variants accept fewer fields; the differences are noted in each section.

## Authentication

Send the management bearer in the `Authorization` header on every request:

```text
Authorization: Bearer <your-management-token>
```

The HQ reads its tokens from startup flags:

| Flag | Token | Accepted on |
|------|-------|-------------|
| `--token` | Management bearer | Every route outside `/mobile/v1` |
| `--chat-token` | Mobile bearer | On this listener, only `/mobile/v1` and `/mobile/v1/*`. It is also the `/ws/chat` token |

The two scopes never overlap. The management bearer is rejected under `/mobile/v1`, and the
mobile bearer is rejected everywhere else. The HQ refuses to start when both tokens are set to the
same value. Relay mode requires both.

Three paths skip the bearer check:

| Path | Why |
|------|-----|
| `GET /health` | Liveness probe |
| `GET /mobile/v1/health` | Liveness probe for native clients |
| `/projects/ws` | WebSocket clients can't send headers. The route checks `?token=` against the management bearer itself |

A missing or wrong bearer returns HTTP `401`:

```json
{ "code": "unauthorized", "error": "Unauthorized", "retryable": false }
```

<Warning>
  If you start the HQ with neither `--token` nor `--chat-token`, authentication is disabled and
  every route accepts unauthenticated requests. Once either token is set, a namespace whose token
  is unset rejects every request with `401`.
</Warning>

### Error shapes

Route groups return one of three error shapes. Each section below says which one it uses.

| Shape | Example | Used by |
|-------|---------|---------|
| Structured | `{"code":"not_found","error":"Agent not found","retryable":false}` | Agents, event replay, sub-agent runtime routes, `401` responses |
| Plain | `{"error":"not found"}` | Most other administrative routes |
| Speech | `{"code":"unavailable","error":"...","retryable":true}` | `/speech/*` |

The management API sets no global body-size limit. The speech routes add their own limits.
Administrative routes send no CORS headers. CORS applies only to `/mobile/v1`; see the
[HQ Mobile API](/api-hq-mobile).

## Health and status

### GET /health

Returns HQ status and the capabilities clients may use. No authentication is required.
**Also under `/mobile/v1`** as `GET /mobile/v1/health`.

```bash
curl http://127.0.0.1:9300/health
```

```json
{
  "status": "healthy",
  "startedAt": "2026-07-12T00:00:00.000Z",
  "pid": 12345,
  "agents": 2,
  "channels": 1,
  "apiVersion": 1,
  "capabilities": ["conversation-sync-v1", "chat-resume-v1", "conversation-control-v2", "speech-v1"]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `status` | `"healthy"` | Always `"healthy"` while the HQ is serving requests |
| `startedAt` | `string` | ISO timestamp for this HQ process |
| `pid` | `number` | HQ process ID |
| `agents` | `number` | Number of registered agents |
| `channels` | `number` | Number of configured messaging channels |
| `apiVersion` | `1` | Mobile API version |
| `capabilities` | `string[]` | Features the client may use |

`conversation-sync-v1`, `chat-resume-v1`, and `conversation-control-v2` are always present.
`speech-v1` appears only while a speech provider can both transcribe and speak. A failure while
checking the speech provider leaves it out rather than failing the request. Ignore capability
strings you don't recognize.

### GET /runtime/status

Returns a current operational snapshot. **Loopback only.**

```bash
curl http://127.0.0.1:9300/runtime/status \
  -H "Authorization: Bearer $DASH_TOKEN"
```

```json
{
  "execution": {
    "accepting": true,
    "activeCanonicalTurns": 2,
    "activeLegacyTurns": 1,
    "quiescingAgents": 0
  },
  "pool": { "size": 3, "maxSize": 64, "pinned": 3, "agents": { "a1": 3 } },
  "channels": [{ "name": "telegram", "health": "connected" }],
  "relay": { "connection": "disabled", "activeStreams": 0 }
}
```

| Field | Description |
|-------|-------------|
| `execution.accepting` | Whether execution is accepting new work |
| `execution.activeCanonicalTurns` | Active conversation turns, including turns still cleaning up after cancellation |
| `execution.activeLegacyTurns` | Active messaging-channel or legacy turns, including cancellation cleanup |
| `execution.quiescingAgents` | Number of agents fenced from admitting new turns |
| `pool` | Current runtime count, capacity, pinned runtime count, and counts by agent ID |
| `channels` | Each running channel's name and health: `connected`, `connecting`, `disconnected`, or `needs_reauth` |
| `relay.connection` | `disabled`, `connecting`, `connected`, `disconnected`, or `stopped` |
| `relay.activeStreams` | Number of streams currently tracked by the relay client |

`GET /health` remains the lightweight liveness check. Runtime status reports process state; it
does not test provider availability or imply that queued work has finished. It contains no
credentials, conversation text, or pending-message contents.

### POST /lifecycle/shutdown

Asks the HQ to shut down gracefully. **Loopback only.** Desktop calls this before it falls back to
a signal. No body is required.

The HQ replies first, then starts shutdown about 100 ms later so the response is not cut off:

```json
{ "ok": true }
```

### GET /identity

Returns the HQ's stable ID and Ed25519 public key. **Also under `/mobile/v1`**, where native
clients call it with the mobile bearer.

```json
{
  "gatewayId": "gateway-01",
  "publicKey": "<base64-public-key>"
}
```

The public key identifies the HQ and is safe to share. The private key never leaves the HQ
machine.

### GET /lan-tls

Returns the SHA-256 fingerprint of the HQ's LAN HTTPS certificate. **Loopback only.** Desktop
reads it to build the pairing QR code, which carries the fingerprint to the phone out of band.
The route exists only when LAN TLS is configured; otherwise it returns `404`.

```json
{ "certificateSha256": "<64 hex characters>" }
```

## Agents

Create and manage agents. Agents are saved to `~/.dash/gateway/agents.json`. Every agent route
is **also under `/mobile/v1`**, where create and update accept fewer fields (see below).

Agent routes use the structured error shape. Responses never include `providerApiKeys`.

| Status | `code` | When |
|--------|--------|------|
| `400` | `validation_failed` | Body is not valid JSON, has an unknown or invalid field, or names an agent that already exists |
| `404` | `not_found` | No agent has this ID |
| `500` | `gateway_offline` | Unexpected HQ error (`retryable: true`) |

### Agent object

```json
{
  "id": "3f9c2a1b",
  "name": "assistant",
  "config": {
    "name": "assistant",
    "model": "anthropic/claude-sonnet-4-20250514",
    "systemPrompt": "You are a helpful assistant.",
    "tools": ["bash", "browser"],
    "workspace": "/Users/you/.dash/workspaces/3f9c2a1b"
  },
  "status": "registered",
  "registeredAt": "2026-07-12T00:00:00.000Z"
}
```

`status` is `registered`, `active`, or `disabled`. `config` holds every configuration field you
set, except `providerApiKeys`.

### Configuration fields

| Field | Type | Notes |
|-------|------|-------|
| `name` | `string` | Required on create; cannot be changed. Nonblank and unique |
| `model` | `string` | Required on create. Nonblank, `provider/model` form |
| `systemPrompt` | `string` | Required on create. May be empty |
| `fallbackModels` | `string[]` | Nonblank strings |
| `tools` | `string[]` | Nonblank tool names. See [Tools](/tools) |
| `skills` | `object` | Only `paths`, `urls`, `learning` (`auto`, `on`, `off`), `minToolCalls` (integer 0 or more) |
| `providerApiKeys` | `object` | Provider ID to key string. Stored, never returned |
| `workspace` | `string` | Omitted or empty assigns a default workspace |
| `maxTokens` | `integer` | 1 or more |
| `mcpServers` | `string[]` | Names of MCP servers this agent may use |
| `swarm` | `object` | Only `enabled`, `maxConcurrentWorkers`, `maxWorkersPerRun`, `maxSteersPerWorker`, `maxRunSeconds`, `allowedModels` |
| `subagents` | `object` | Only `enabled`, `delegation` (`auto` or `explicit`), `allowedTypes`, `allowedModels`, `maxConcurrent`, `maxPerTurn`, `maxRunSeconds`, `maxDepth`, `modelAliases`. See [Configuration](/configuration) |
| `plugins` | `string[]` or `null` | Plugins this agent may use. `null` clears the list |
| `providers` | `string[]` or `null` | Providers this agent may use. `null` clears the list |

Any other key returns `400`. Numeric caps must be positive integers, except
`swarm.maxSteersPerWorker` and `subagents.maxDepth`, which also accept `0`. `modelAliases` maps a
bare alias (no `/`) to a model ID. Memory settings have their own routes; see [Memory](#memory).

### GET /agents

Lists every agent as an array of agent objects.

```bash
curl http://127.0.0.1:9300/agents \
  -H "Authorization: Bearer $DASH_TOKEN"
```

### POST /agents

Creates an agent and returns it with HTTP `201`. `name`, `model`, and `systemPrompt` are required.
Under `/mobile/v1`, only those three fields are accepted.

```bash
curl -X POST http://127.0.0.1:9300/agents \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "assistant",
    "model": "anthropic/claude-sonnet-4-20250514",
    "systemPrompt": "You are a helpful assistant.",
    "tools": ["bash"]
  }'
```

### GET /agents/:id

Returns one agent object.

### PUT /agents/:id

Updates an agent's configuration and returns the updated agent. Send only the fields to change;
the body must not be empty. `name` cannot be changed. Under `/mobile/v1`, only `model` and
`systemPrompt` are accepted.

```bash
curl -X PUT http://127.0.0.1:9300/agents/3f9c2a1b \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model": "anthropic/claude-opus-4-5"}'
```

A change to `swarm` or `subagents` restarts the agent's warm runtimes so the next turn uses the new
settings. Other changes are read on the next turn.

### DELETE /agents/:id

Deletes an agent and returns `{"ok": true}`. The HQ cancels the agent's running turns and swarm
runs, removes it from messaging-channel routing, and deletes its browser sessions. Its
conversations are archived, not deleted: their messages stay readable through the
[conversation routes](/api-hq-mobile).

### POST /agents/:id/disable

Disables an agent without deleting it and returns `{"ok": true}`. The HQ stops admitting new turns
for it, cancels its running turns and swarm runs, and releases its runtimes.

### POST /agents/:id/enable

Re-enables a disabled agent and returns `{"ok": true}`.

### POST /agents/:agentId/conversation-title

Generates a short title for a conversation from its first message. **Loopback only.** The title is
produced by one small completion on the agent's own model. When projects exist, the same call also
picks the active project the conversation best fits.

| Field | Type | Description |
|-------|------|-------------|
| `text` | `string` | Required. The message to title. Whitespace is trimmed |

```json
{ "title": "Release planning", "project": { "id": "01J...", "key": "WEB" } }
```

`project` is `null` when no project fits. Errors use the plain shape: `400` for a missing `text`,
`404` for an unknown agent, and `502` when the completion fails.

## Memory

Read and edit what an agent remembers across conversations. See [Memory](/memory). The list,
read, and delete routes are **also under `/mobile/v1`**. Writing a memory and the settings
routes are **loopback only**.

Memory routes use the plain error shape, including under `/mobile/v1`:

| Status | When |
|--------|------|
| `400` | Invalid JSON, a body that isn't an object, or an invalid name, description, type, or content |
| `404` | Unknown agent or memory |
| `409` | The agent already has 200 memories and this write would add another |
| `503` | Memory is disabled for this agent (writes only), or the HQ has no memory directory |

### GET /agents/:id/memory

Lists an agent's memories without their bodies. It lists what is on disk even when memory is
disabled for the agent.

```json
[
  {
    "name": "preferred-editor",
    "description": "User edits code in Neovim",
    "type": "user",
    "source": "agent",
    "createdAt": "2026-07-12",
    "updatedAt": "2026-07-12",
    "size": 58
  }
]
```

`type` is `user`, `feedback`, `project`, or `reference`. `source` records who wrote it: `agent`,
`sweep`, `user`, or `import`. `size` is the body length in characters.

### GET /agents/:id/memory/:name

Returns one memory, including its `content`, with the same fields as the list minus `size`.

### PUT /agents/:id/memory/:name

Creates or replaces a memory. The name comes from the path. Memories written here are recorded
with `source: "user"`.

| Field | Type | Rules |
|-------|------|-------|
| `description` | `string` | One line, 1 to 200 characters |
| `type` | `string` | `user`, `feedback`, `project`, or `reference` |
| `content` | `string` | 1 to 2,048 characters |

The name must be lowercase letters, digits, and hyphens, starting with a letter or digit, at most
64 characters.

```bash
curl -X PUT http://127.0.0.1:9300/agents/3f9c2a1b/memory/preferred-editor \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"description": "User edits code in Neovim", "type": "user", "content": "Prefers Neovim."}'
```

```json
{
  "record": {
    "name": "preferred-editor",
    "description": "User edits code in Neovim",
    "type": "user",
    "source": "user",
    "createdAt": "2026-07-12",
    "updatedAt": "2026-07-12",
    "content": "Prefers Neovim."
  },
  "action": "created"
}
```

`action` is `created` or `updated`.

### DELETE /agents/:id/memory/:name

Deletes a memory and returns its name. This works while memory is disabled.

```json
{ "name": "preferred-editor" }
```

### GET /agents/:id/memory/config

Returns the agent's memory settings. An agent that has never set them reads as enabled with
`sweep: "auto"`.

```json
{ "enabled": true, "sweep": "auto" }
```

### PATCH /agents/:id/memory/config

Changes memory settings and returns the merged result. Omitted fields keep their current values.

| Field | Type | Description |
|-------|------|-------------|
| `enabled` | `boolean` | `false` turns off the memory prompt, the memory tools, and the post-turn sweep |
| `sweep` | `string` | `auto`, `on`, or `off`. Controls the post-turn review that saves memories |

Changing `enabled` restarts the agent's warm runtimes so the next turn gains or loses the memory
tools. A `sweep` change applies on the next turn.

## Skills

Manage the skills an agent can load. See [Skills](/skills). Only `GET /agents/:id/skills` is
**also under `/mobile/v1`**, as a read-only view; every other skill route is **loopback only**.

Skill routes use the plain error shape:

| Status | When |
|--------|------|
| `400` | Invalid JSON, or an invalid `learning` or `minToolCalls` setting |
| `404` | Unknown agent, skill, or lesson |
| `409` | A skill with that name already exists |
| `422` | The skill is invalid, belongs to a plugin, failed its security scan, or was judged dangerous |

### GET /agents/:id/skills

Lists every skill available to the agent, from plugins and from the agent itself.

```json
[
  {
    "name": "release-notes",
    "description": "Write release notes from merged PRs",
    "trigger": "when asked for release notes",
    "location": "/Users/you/.dash/gateway/skills/assistant/release-notes/SKILL.md",
    "content": "...",
    "editable": true,
    "source": "managed"
  }
]
```

`source` is `managed`, `agent` (learned by the agent), `remote`, or `plugin`. Under `/mobile/v1`,
each entry has only `name`, `description`, `trigger`, `source`, and `content`.

### POST /agents/:id/skills

Creates a skill and returns HTTP `201` with its name and file location.

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Skill name |
| `description` | `string` | One-line description shown to the agent |
| `content` | `string` | The skill's instructions |

```json
{ "name": "release-notes", "location": "/Users/you/.dash/gateway/skills/assistant/release-notes/SKILL.md" }
```

### GET /agents/:id/skills/:name

Returns one skill with the same fields as the list.

### PUT /agents/:id/skills/:name

Replaces a skill's body and keeps its frontmatter. Send `{"content": "..."}`. Returns the skill's

### DELETE /agents/:id/skills/:name

Removes a skill and returns `{"name": "..."}`. Plugin skills cannot be removed here.

### POST /agents/:id/skills/install

Installs a skill from a git repository, URL, or local path. The skill is security-scanned before
it is installed, and installation fails closed.

| Field | Type | Description |
|-------|------|-------------|
| `source` | `string` | Required. Where to fetch the skill from |
| `name` | `string` | Optional name to install it under |

```json
{
  "name": "release-notes",

```

`verdict.verdict` is `safe` or `suspicious`. A `dangerous` skill is rejected with `422`.

### GET /agents/:id/skills/config

Returns the agent's `skills` configuration, or `{}` when none is set.

```json
{ "paths": ["/opt/skills"], "learning": "auto", "minToolCalls": 3 }
```

Merges fields into the agent's `skills` configuration and returns the result.

|-------|------|-------------|
| `paths` | `string[]` | Extra local skill directories |

### GET /agents/:id/skills/:name/lessons

Returns the lesson book for a skill the agent learned. Returns `404` when the skill has no lesson

```json
{

```

### DELETE /agents/:id/skills/:name/lessons/:lessonId

Retires one lesson and returns the updated lesson book. The lesson moves to `retired`; it is not
deleted, and a later review will not propose it again.

## Sub-agents

Manage the helper agents an agent can start, and the sub-agents already running. Every route in
this section is **also under `/mobile/v1`**.

**Definitions.** The five definition routes read and write the per-agent sub-agent types. On the
loopback API they use the plain error shape; under `/mobile/v1` they use the structured shape. A
definition
`:name` must be lowercase letters, digits, and hyphens, starting with a letter or digit. Any other
name returns `400`. An unknown agent returns `404`.

### GET /agents/:id/subagent-types

Returns the agent's resolved roster: built-in types plus workspace, plugin, and per-agent
definitions.

```json
{
  "types": [
    {
      "name": "reviewer",
      "description": "Reviews a diff for correctness",
      "source": "agent",
      "tools": ["read", "grep"],
      "model": "anthropic/claude-sonnet-4-20250514",
      "background": false
    }
  ],
  "unknownAllowedTypes": ["reveiwer"]
}
```

Each type can also carry `location`, `disallowedTools`, `skills`, `maxTurns`, `isolation`
(`worktree`), and `shadowedBy`. The system prompt is left out; read it from the definition route.
`unknownAllowedTypes` lists names in the agent's `subagents.allowedTypes` that match no type,
which usually means a typo.

### GET /agents/:id/subagent-definitions

Lists the definition files in the agent's own writable directory. Workspace and plugin
definitions appear only in the roster.

```json
{ "definitions": [{ "name": "reviewer", "file": "reviewer.md" }] }
```

### GET /agents/:id/subagent-definitions/:name

Returns one definition's raw Markdown.

```json
{ "name": "reviewer", "raw": "---\nname: reviewer\ndescription: Reviews a diff\n---\nYou review diffs." }
```

### PUT /agents/:id/subagent-definitions/:name

Writes a definition and returns `{"ok": true, "name": "reviewer"}`. Send `{"raw": "..."}` with the
full Markdown file, frontmatter included.

| Status | When |
|--------|------|
| `400` | Invalid JSON, empty `raw`, or `raw` over 256 KiB |
| `422` | The definition does not parse, or its frontmatter `name` differs from `:name` |

The HQ validates the definition before writing it. The agent picks up the change on its next
model turn.

### DELETE /agents/:id/subagent-definitions/:name

Deletes a definition file and returns `{"ok": true, "name": "reviewer"}`. Returns `404` when the
file doesn't exist.

**Running sub-agents.** The conversation, stop, and resume routes use the structured error shape on
both mounts.

### GET /conversations/:id/subagents

Lists the sub-agents started from a conversation. The list is read from saved state, so it still
works after an HQ restart.

```json
{
  "subagents": [
    {
      "id": "sub_01J...",
      "name": "reviewer-1",
      "type": "reviewer",
      "description": "Review the auth diff",
      "status": "done",
      "background": true,
      "depth": 1,
      "startedAt": "2026-07-12T00:00:00.000Z",
      "endedAt": "2026-07-12T00:02:10.000Z",
      "usage": { "inputTokens": 12000, "outputTokens": 900 },
      "toolCallCount": 7,
      "report": "No blocking issues found.",
      "oneShot": false
    }
  ]
}
```

`status` is `running`, `waiting_input`, `done`, `failed`, `cancelled`, `interrupted`, or
`max_turns`. `report` is scanned before it is returned. `oneShot` types, such as `Explore` and
`Plan`, cannot be resumed. An unknown conversation returns `404 not_found`.

### POST /subagents/:id/stop

Stops a sub-agent and every sub-agent it started. No body is required.

```json
{ "ok": true, "status": "cancelled" }
```

Returns `404 not_found` when `:id` isn't a sub-agent, and `409` when the sub-agent has already
finished.

### POST /subagents/:id/resume

Sends a sub-agent a follow-up message, exactly as its parent would with the `send_message` tool.

| Field | Type | Description |
|-------|------|-------------|
| `message` | `string` | Required. Nonblank |
| `requestId` | `string` | Optional correlation ID, up to 256 characters. Echoed on the `accepted` chat frame of the turn it starts |

```json
{ "ok": true, "status": "running", "mode": "resumed" }
```

`mode` is `resumed` when the message starts a new turn, or `queued` when it is delivered to a
running sub-agent. Returns `400` for an invalid body, `404` for an unknown sub-agent, and `409`
when the sub-agent can't take the message: a one-shot type, a spent steer cap, or no parent
conversation.

## Swarm panel

Inspect and steer an agent's swarm runs. A run is the set of sub-agents one parent turn started.
Every route here is **loopback only** and uses the plain error shape; an unknown agent or run
returns `404`.

### GET /agents/:id/swarm/runs

Lists the agent's recent runs, including runs from before the last HQ restart.

```json
{
  "runs": [
    {
      "runId": "run_01J...",
      "agentId": "3f9c2a1b",
      "conversationId": "018f0f4a-...",
      "startedAt": 1752278400000,
      "endedAt": 1752278530000,
      "finalized": true,
      "workerCount": 2,
      "activeCount": 0
    }
  ]
}
```

`startedAt` and `endedAt` are epoch milliseconds.

### GET /agents/:id/swarm/runs/:runId

Returns one run with the same fields plus a `workers` array of per-worker snapshots.

### POST /agents/:id/swarm/runs/:runId/workers/:workerId/cancel

Cancels one worker. Returns `{"ok": true}`, or `409` with `{"ok": false, "reason": "..."}` when the
worker can't be cancelled. This also works for a background worker whose spawning turn has ended.

### POST /agents/:id/swarm/runs/:runId/workers/:workerId/send

Sends one worker a message. Send `{"message": "..."}`; an empty message returns `400`. Returns
`{"ok": true}`, or `409` with `{"ok": false, "reason": "..."}` when the worker can't accept it.

### POST /agents/:id/conversations/:conversationId/swarm/cancel

Cancels every unfinished worker in the conversation's live swarm turn. Workers keep running after
the chat stream ends, so this is how the stop button reaches them.

```json
{ "cancelled": true }
```

`cancelled` is `false` when there was no live turn. Calling it again is safe.

## Browser

Manage the browser agents use and the saved logins in their browser profiles. See
[Browser](/browser). Every route here is **loopback only**.

Browser routes use the plain error shape. An invalid profile name returns `400`, a profile in use
by a running browser returns `409`, and an unknown agent returns `404`.

### GET /browser/status

Returns which browser the HQ will launch, the managed-download progress, and the number of live
browser sessions.

| Query | Description |
|-------|-------------|
| `refresh=1` | Search for a browser again instead of using the cached result. Any other value is a plain read |

```json
{
  "source": "chrome",
  "path": "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome",
  "install": { "state": "idle", "done": 0, "total": 0 },
  "liveSessions": 1,
  "sizes": { "downloadMb": 190, "diskMb": 370 }
}
```

| Field | Description |
|-------|-------------|
| `source` | `config`, `chrome`, `edge`, `managed`, or `null` when no working browser was found |
| `path` | The browser executable, when one was found |
| `managedBuildId` | The installed managed build, if any |
| `unverifiedPath`, `unverifiedSource` | A browser found on disk that did not start in time. Retry rather than download |
| `install.state` | `idle`, `downloading`, `verifying`, `done`, or `failed`, with byte counts `done` and `total` and an optional `error` |
| `liveSessions` | Browser sessions currently open |
| `sizes` | Approximate download and disk size of the managed browser, in MB |

### POST /browser/install

Starts downloading the managed browser and returns HTTP `202` immediately with the current

returns the same `202` and does not start a second download. A failed download shows up as

```json

```

### GET /agents/:id/browser/profiles

Lists the agent's saved browser profiles.

```json
{

    { "name": "work", "lastUsedAt": "2026-07-12T00:00:00.000Z", "sizeBytes": 41943040, "inUse": false }
  ]
}
```

### DELETE /agents/:id/browser/profiles/:name

Deletes a saved profile, including its cookies and logins, and returns `{"name": "work"}`.
Returns `409` while the profile is in use.

## Channels

Connect and manage messaging apps such as Telegram and WhatsApp. See
[Messaging Apps](/messaging-apps). Channels are saved to `~/.dash/gateway/channels.json`. Every
route here is **loopback only** and uses the plain error shape.

| Status | When |
|--------|------|
| `400` | Invalid JSON, a missing required field, a field of the wrong type, or routing that names an unknown agent |
| `404` | Unknown channel |
| `409` | A channel with that name already exists |

### Channel object

```json
{
  "name": "family-telegram",
  "adapter": "telegram",
  "globalDenyList": [],
  "allowedUsers": ["123456789"],
  "routing": [
    {
      "condition": { "type": "default" },
      "agentId": "3f9c2a1b",
      "allowList": [],
      "denyList": []
    }
  ],
  "registeredAt": "2026-07-12T00:00:00.000Z"
}
```

`adapter` is `telegram` or `whatsapp`. A routing `condition` is `{"type": "default"}`,
`{"type": "sender", "ids": [...]}`, or `{"type": "group", "ids": [...]}`.

### GET /channels

Lists every channel as an array of channel objects.

### POST /channels

Creates a channel, starts its adapter, and returns HTTP `201` with `{"ok": true}`.

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Required. Unique channel name |
| `adapter` | `string` | Required. `telegram` or `whatsapp` |
| `routing` | `array` | Required. Routing rules; every `agentId` must exist |
| `globalDenyList` | `string[]` | Optional. Senders ignored on every route |
| `allowedUsers` | `string[]` | Optional. Senders allowed to use the channel |

Store the channel's credential first with `POST /credentials`: a Telegram bot token under
`channel:<name>:token`, or WhatsApp auth JSON under `channel:<name>:whatsapp-auth`. Without it,
creation fails with `400`.

```bash
curl -X POST http://127.0.0.1:9300/channels \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "family-telegram",
    "adapter": "telegram",
    "routing": [{"condition": {"type": "default"}, "agentId": "3f9c2a1b", "allowList": [], "denyList": []}]
  }'
```

### GET /channels/:name

Returns one channel object. URL-encode the name.

### PUT /channels/:name

Updates a channel and returns the updated channel object. Send any of `routing`,
`globalDenyList`, and `allowedUsers`; omitted fields are unchanged. Each must be an array.

### DELETE /channels/:name

Stops the channel's adapter, removes the channel, and returns `{"ok": true}`.

## Credentials

Store provider API keys and messaging tokens in the HQ's encrypted store
(`~/.dash/gateway/credentials.enc`). See [Secrets](/secrets). Every route here is
**loopback only** and uses the plain error shape.

Two key formats have special meaning:

| Key | Meaning |
|-----|---------|
| `<provider>-api-key:<name>` | A provider API key, for example `anthropic-api-key:default`. Setting or deleting one refreshes the model list and speech availability |
| `channel:<name>:token` | A Telegram bot token. Setting it restarts that channel with the new token |

### GET /credentials

Lists stored credential keys. Values are never returned.

```json
["anthropic-api-key:default", "channel:family-telegram:token"]
```

### POST /credentials

Sets one credential and returns HTTP `201` with `{"ok": true}`. Both `key` and `value` are
required and must be nonempty.

```bash
curl -X POST http://127.0.0.1:9300/credentials \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key": "anthropic-api-key:default", "value": "sk-ant-..."}'
```

Running agents pick up the new value on their next turn.

### DELETE /credentials/:key

Deletes a credential and returns `{"ok": true}`. URL-encode the key.

Phones and the web app manage provider API keys, and sign in with a Claude or ChatGPT
subscription, through the Mobile API's [AI providers](/api-hq-mobile#ai-providers) routes.

## Models

List the models agents can use. See [AI Providers](/ai-providers). `GET /models` is **also under
`/mobile/v1`** as a read-only view; `POST /models/refresh` is **loopback only**.

The HQ fetches each configured provider's model list, filters it through its bundled provider
catalogs, and caches the result for six hours. A provider that fails is retried after five
minutes, and its last good models are kept meanwhile. Setting or deleting a provider API key
clears the cache. With no provider keys at all, the response lists every catalog's built-in
models with `source: "bootstrap"`.

### GET /models

```bash
curl http://127.0.0.1:9300/models \
  -H "Authorization: Bearer $DASH_TOKEN"
```

```json
{
  "models": [
    { "value": "anthropic/claude-opus-4-5", "label": "Claude Opus 4.5", "provider": "anthropic" }
  ],
  "source": "live",
  "errors": {},
  "fetchedAt": "2026-07-12T00:00:00.000Z",
  "supportedModelsReviewedAt": "2026-07-01"
}
```

| Field | Description |
|-------|-------------|
| `models[].value` | The `provider/model` ID to use in an agent's `model` field |
| `source` | `live` after a provider fetch, `bootstrap` when no provider key is configured |
| `errors` | Provider ID to fetch error, for providers that failed |
| `fetchedAt` | When the list was fetched |
| `supportedModelsReviewedAt` | Review date of the newest provider catalog |

On the loopback API, `?debug=true` adds `bootstrap` (the catalogs' built-in models), `patterns`,
`providersConfigured`, and `providersAvailable`. Under `/mobile/v1`, any query parameter returns
`400` with the structured `validation_failed` error.

### POST /models/refresh

Fetches the model list again, ignoring the cache, and returns the same shape as `GET /models`.

## Speech

Dictation and read-aloud. Every speech route is **also under `/mobile/v1`**, with an identical
handler. Hands-free voice mode runs over the chat WebSocket instead; see
[HQ Chat WebSocket](/api-hq-chat-websocket#voice-mode).

Speech errors use the structured shape and pass the provider-level code through:

| Status | `code` | Meaning |
|--------|--------|---------|
| `400` | `validation_failed` | Malformed request |
| `400` | `invalid` | The provider rejected the request as invalid |
| `401` | `unauthorized` | The provider rejected its API key. This is not an HQ bearer failure |
| `413` | `too_large` | Body or audio over a size limit |
| `413` | `too_long` | Text over 4,000 characters |
| `502` | `provider` | The provider returned an error |
| `502` | `network` | The HQ couldn't reach the provider (`retryable: true`) |
| `503` | `unavailable` | No speech provider is configured (`retryable: true`) |

### GET /speech/config

Returns the current speech configuration and each provider's availability.

```json
{
  "config": {
    "stt": { "provider": "openrouter", "model": "openai/whisper-large-v3" },
    "tts": { "provider": "openrouter", "model": "minimax/speech-2.8-turbo", "voice": "English_expressive_narrator" },
    "realtime": { "provider": null }
  },
  "providers": [
    {
      "id": "openrouter",
      "capabilities": { "transcription": true, "speech": true, "realtime": false },
      "available": true
    },
    {
      "id": "realtime",
      "capabilities": { "transcription": false, "speech": false, "realtime": true },
      "available": false,
      "reason": "no_provider_offers_realtime"
    }
  ]
}
```

An unavailable provider carries a `reason`: `no_credential` or `no_provider_offers_realtime`.
`stt.language` is present only when a language is pinned, and `tts.speed` only when set.

### PATCH /speech/config

Merges a partial configuration, saves it, and returns the same shape as `GET /speech/config`.
Omitted keys keep their current values. An unknown key anywhere in the body returns `400`.

| Field | Rules |
|-------|-------|
| `stt.provider`, `stt.model` | Nonempty, at most 200 characters |
| `stt.language` | 2 to 8 characters, or `null` to return to auto-detection |
| `tts.provider`, `tts.model`, `tts.voice` | Nonempty, at most 200 characters |
| `tts.speed` | Number from 0.25 to 4 |
| `realtime.provider` | Required when `realtime` is sent. A string or `null` |

```bash
curl -X PATCH http://127.0.0.1:9300/speech/config \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"stt": {"language": null}}'
```

A declared `Content-Length` above 64 KiB returns `413 too_large` before the body is read.

### GET /speech/models

Lists the models the configured provider offers for one kind.

| Query | Description |
|-------|-------------|
| `kind` | Required. `transcription` or `speech` |

```json
{
  "models": [
    { "id": "minimax/speech-2.8-turbo", "name": "MiniMax Speech 2.8 Turbo", "kind": "speech", "voices": ["English_expressive_narrator"] }
  ]
}
```

### POST /speech/transcriptions

Transcribes one recorded clip. Audio is sent inline as base64 JSON, not multipart.

| Field | Type | Description |
|-------|------|-------------|
| `audio` | `string` | Required. Base64 audio, at most 8 MiB decoded, not empty |
| `format` | `string` | Required. `wav`, `m4a`, `mp3`, `flac`, `ogg`, `webm`, or `aac` |
| `language` | `string` | Optional language hint |

```bash
curl -X POST http://127.0.0.1:9300/speech/transcriptions \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"audio": "<base64>", "format": "m4a"}'
```

```json
{ "text": "Hello from DashSquad.", "durationSeconds": 1.8 }
```

`durationSeconds` is present only when the provider reports it. A declared `Content-Length` above
12 MiB returns `413 too_large` before the body is read.

### POST /speech/speech

Synthesizes speech from text. Send `{"text": "..."}`, 1 to 4,000 characters.

```bash
curl -X POST http://127.0.0.1:9300/speech/speech \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello from DashSquad."}' \
  --output reply.mp3
```

The success body is audio, not JSON. It streams as `audio/mpeg`, except for a PCM-only model
(currently Google's Gemini TTS), which returns a complete `audio/wav` file. An error raised before
the first audio chunk is still JSON, so accept `audio/mpeg`, `audio/wav`, and `application/json`.
A declared `Content-Length` above 64 KiB returns `413 too_large`.

## MCP servers

Connect Model Context Protocol servers whose tools agents can use. Every route here is
**loopback only** and uses the plain error shape. A server's tools are named
`<server>__<tool>`. Add a server to an agent by listing its name in the agent's `mcpServers`.

### MCP server object

```json
{
  "name": "github",
  "transport": { "type": "streamable-http", "url": "https://mcp.example.com/github" },
  "status": "connected",
  "tools": ["github__search_issues", "github__create_issue"]
}
```

`transport` is one of:

| `type` | Fields |
|--------|--------|
| `stdio` | `command`, optional `args` |
| `sse` | `url`, optional `headers` |
| `streamable-http` | `url`, optional `headers` |

`status` is `connected`, `disconnected`, `reconnecting`, `error`, or `needs_reauth`.

### GET /runtime/mcp/servers

Lists every saved MCP server as an array of MCP server objects.

### POST /runtime/mcp/servers

Connects a new MCP server, saves it, and returns HTTP `201`.

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Required. Letters, digits, `-`, and `_` |
| `transport` | `object` | Required. See the table above |
| `env` | `object` | Optional environment variables for a `stdio` server |
| `auth` | `object` | Optional OAuth settings: `type: "oauth"`, `grantType`, `clientId`, `clientSecret`, `scopes` |
| `toolTimeout` | `number` | Optional tool-call timeout in milliseconds. Default 60,000 |
| `maxReconnectAttempts` | `number` | Optional |

```bash
curl -X POST http://127.0.0.1:9300/runtime/mcp/servers \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "files", "transport": {"type": "stdio", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]}}'
```

```json
{ "status": "connected", "serverName": "files", "tools": ["files__read_file", "files__list_directory"] }
```

| Status | When |
|--------|------|
| `400` | Invalid JSON, or `name` or `transport` missing |
| `403` | The server URL is not on the allowlist |
| `409` | A server with that name already exists |
| `500` | The connection failed |

### GET /runtime/mcp/servers/:name

Returns one MCP server object.

### DELETE /runtime/mcp/servers/:name

Disconnects and removes a server, removes it from every agent's `mcpServers`, and returns
`{"ok": true}`.

### POST /runtime/mcp/servers/:name/reconnect

Disconnects and reconnects a saved server.

```json
{ "ok": true, "status": "connected" }
```

### POST /runtime/mcp/servers/:name/reauthorize

Restarts sign-in for a server whose status is `needs_reauth`. Returns
`{"ok": true, "status": "..."}`, `404` for an unknown server, or `500` when the server is in any
other state.

### GET /runtime/mcp/allowlist

Returns the URL patterns that remote MCP servers must match, as an array of strings. An empty
list allows every URL. `stdio` servers are not checked.

### PUT /runtime/mcp/allowlist

Replaces the allowlist. Send a JSON array of strings; `*` matches any run of characters.

```bash
curl -X PUT http://127.0.0.1:9300/runtime/mcp/allowlist \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '["https://mcp.example.com/*"]'
```

```json
{ "ok": true, "count": 1 }
```

## Plugins

Install and manage plugins. See [Plugins](/plugins). Every route here is **loopback only** and uses
the plain error shape. Changes are saved first and then applied by reloading every plugin.

### GET /plugins

Lists every plugin, including disabled and failed ones, sorted by name.

```json
{
  "records": [
    {
      "name": "demo",
      "displayName": "Demo",
      "version": "1.0.0",
      "description": "A demo plugin",
      "status": "loaded",
      "dir": "/Users/you/.dash/gateway/plugins/demo",
      "skillDirs": ["/Users/you/.dash/gateway/plugins/demo/skills"],
      "activated": ["skills"],
      "noop": ["bin", "mcp"]
    }
  ]
}
```

`status` is `loaded`, `disabled`, or `error`. `activated` lists the component kinds in use; `noop`
lists kinds present but not active, such as code components of an untrusted plugin. A built-in
plugin has `builtin: true`. A failed plugin has `failure` with `phase` (`discovery`, `manifest`, or
`route`), `error`, and `failedAt`.

### POST /plugins/install

Fetches, scans, and installs a plugin, then reloads. The plugin is enabled but not trusted: its
code components stay inactive until you trust it with `PUT /plugins/:name`.

| Field | Type | Description |
|-------|------|-------------|
| `source` | `string` | Required. Where to fetch the plugin from |
| `name` | `string` | Optional name to install it under |

```bash
curl -X POST http://127.0.0.1:9300/plugins/install \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"source": "git:owner/repo"}'
```

Returns HTTP `201`:

```json
{
  "name": "demo",
  "version": "1.0.0",
  "description": "A demo plugin",
  "location": "/Users/you/.dash/gateway/plugins/demo",
  "scanVerdict": "safe",
  "scanReasons": [],
  "source": "git:owner/repo"
}
```

If the install succeeds but the reload fails, the plugin is still installed. The HQ returns HTTP
`200` with `{"ok": true, "installed": {...}, "note": "...", "error": "..."}`, and the next reload
picks it up.

| Status | When |
|--------|------|
| `400` | Invalid JSON or an empty `source` |
| `404` | The source was not found |
| `409` | A plugin with that name exists, or the name belongs to a built-in plugin |
| `422` | Invalid manifest, corrupt archive, failed scan, or a plugin judged dangerous |

### PUT /plugins/:name

Enables, disables, trusts, or untrusts a plugin, then reloads and returns its updated record.

| Field | Type | Description |
|-------|------|-------------|
| `enabled` | `boolean` | Whether the plugin loads |
| `trusted` | `boolean` | Whether its code components, such as MCP servers and executables, run |

```bash
curl -X PUT http://127.0.0.1:9300/plugins/demo \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"trusted": true}'
```

Returns `400` for a non-boolean field and `404` for an unknown plugin. If the reload fails, or the
plugin is missing afterward, it returns `409` with `error`, `plugin`, and `note`: the setting was
saved, but the running plugins are unchanged.

### DELETE /plugins/:name

Removes a plugin's saved settings and, for a plugin installed through this API, deletes its
directory. Then reloads.

```json
{ "ok": true, "path": "/Users/you/.dash/gateway/plugins/demo" }
```

`path` is present only when a directory was deleted. A built-in plugin returns `400`; disable it
instead. An unknown plugin returns `404`. If the reload fails after removal, the response is `409`
with `ok: true`, `removed: true`, `error`, and `note`: the removal stuck.

### POST /plugins/reload

Rediscovers plugins without changing any settings.

```json
{ "ok": true, "reloadedAt": "2026-07-12T00:00:00.000Z" }
```

A failed reload returns `500` with `{"error": "..."}`.

### GET /runtime/plugins

Returns a compact view for model and credential pickers: providers contributed by plugins, and
every plugin that isn't disabled.

```json
{
  "providers": [
    { "id": "myllm", "label": "MyLLM", "credentialPrefix": "myllm-api-key", "pluginName": "myllm-provider", "ui": {} }
  ],
  "plugins": [{ "name": "demo", "displayName": "Demo", "version": "1.0.0" }]
}
```

## Projects, issues and inbox

Track work in projects and issues. See [Projects](/projects). Every route here is
**loopback only** and uses the plain error shape. Wherever a path takes a project or issue `:id`,
you can pass its ID or its key, such as `WEB` or `WEB-12`. Body fields and query filters, such
as `project_id`, take IDs only.

Writes through this API are recorded as made by the local human user. Live updates are pushed over
the `/projects/ws` WebSocket; see [HQ Chat WebSocket](/api-hq-chat-websocket#projects-websocket).

### Project object

```json
{
  "id": "01J2...",
  "key": "WEB",
  "name": "Website",
  "description": "Marketing site rebuild",
  "status": "active",
  "created_at": "2026-07-12T00:00:00.000Z",
  "updated_at": "2026-07-12T00:00:00.000Z",
  "archived_at": null
}
```

`status` is `active`, `paused`, `completed`, or `cancelled`.

### Issue object

```json
{
  "id": "01J3...",
  "key": "WEB-12",
  "project_id": "01J2...",
  "parent_issue_id": null,
  "title": "Fix the pricing table",
  "description": "",
  "status": "todo",
  "sub_status": null,
  "assignee_user_id": "local",
  "created_by": "human",
  "created_by_agent_id": null,
  "created_at": "2026-07-12T00:00:00.000Z",
  "updated_at": "2026-07-12T00:00:00.000Z",
  "completed_at": null
}
```

`status` is `backlog`, `todo`, `in_progress`, `review`, `done`, or `cancelled`. `sub_status` is
`waiting_on_human`, `agent_working`, `blocked`, or `null`. An issue with no project gets a `TASK-`
key.

### GET /projects

Lists projects as an array. Filter with `?status=`; an invalid status returns `400`.

### POST /projects

Creates a project and returns it with HTTP `201`.

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Required |
| `key` | `string` | Required. Prefix for issue keys |
| `description` | `string` | Optional |

A rejected project, such as a duplicate key, returns `400`.

### GET /projects/:id

Returns a project plus `issue_counts_by_status`, a count for every issue status.

### PATCH /projects/:id

Updates any of `name`, `description`, `status`, and `archived_at` (a timestamp or `null`), and
returns the project. Other keys are ignored.

### GET /projects/:id/issues

Lists a project's issues as an array.

### GET /issues

Lists issues as an array. Every query parameter is an optional filter:

| Query | Description |
|-------|-------------|
| `project_id` | Issues in one project |
| `status` | One issue status. Invalid values return `400` |
| `sub_status` | One sub-status. Invalid values return `400` |
| `assignee_user_id` | Issues assigned to one user |
| `created_by` | `human` or `agent` |
| `parent_issue_id` | Subtasks of one issue |
| `agents_involved` | Issues an agent has worked on |

### POST /issues

Creates an issue and returns it with HTTP `201`.

| Field | Type | Description |
|-------|------|-------------|
| `title` | `string` | Required |
| `project_id` | `string` or `null` | Optional. `null` makes a standalone issue |
| `parent_issue_id` | `string` or `null` | Optional. Makes this a subtask |
| `description` | `string` | Optional |
| `assignee_user_id` | `string` | Optional |
| `status` | `string` | Optional issue status |
| `sub_status` | `string` or `null` | Optional sub-status |

```bash
curl -X POST http://127.0.0.1:9300/issues \
  -H "Authorization: Bearer $DASH_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title": "Fix the pricing table", "project_id": "01J2...", "status": "todo"}'
```

### GET /issues/:id

Returns an issue plus `comments`, `events`, `linked_sessions`, and `subtasks`.

### PATCH /issues/:id

Updates any of `title`, `description`, `status`, `sub_status`, `assignee_user_id`, `project_id`,
and `completed_at`, and returns the issue. Other keys are ignored. An invalid `status` or
`sub_status` returns `400`.

### DELETE /issues/:id

Deletes an issue and returns `{"ok": true}`.

### POST /issues/:id/comments

Adds a comment and returns it with HTTP `201`. Send `{"body": "..."}`; an empty body returns `400`.

```json
{
  "id": "01J4...",
  "issue_id": "01J3...",
  "author_type": "human",
  "author_id": "local",
  "body": "Looks good.",
  "created_at": "2026-07-12T00:00:00.000Z",
  "updated_at": "2026-07-12T00:00:00.000Z",
  "deleted_at": null
}
```

### PATCH /issues/:id/comments/:commentId

Edits a comment's text and returns the comment. Send `{"body": "..."}`. An unknown comment returns
`404`.

### DELETE /issues/:id/comments/:commentId

Soft-deletes a comment and returns `{"ok": true, "issue_id": "..."}`.

### GET /issues/:id/events

Returns the issue's history as an array. Each event has `id`, `issue_id`, `type`, `actor_type`
(`human`, `agent`, or `system`), `actor_id`, `data`, and `created_at`.

### GET /issues/:id/sessions

Lists the chat sessions linked to an issue.

```json
[
  {
    "session_id": "018f0f4a-...",
    "issue_id": "01J3...",
    "agent_id": "3f9c2a1b",
    "first_referenced_at": "2026-07-12T00:00:00.000Z",
    "last_referenced_at": "2026-07-12T00:05:00.000Z",
    "reference_count": 3
  }
]
```

### POST /issues/:id/sessions

Links a chat session to an issue and returns the link with HTTP `201`.

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | `string` | Required |
| `agent_id` | `string` or `null` | Optional. The agent working in that session |

### GET /inbox

Lists the issues waiting for the local user.

```json
[
  {
    "issue": { "id": "01J3...", "key": "WEB-12", "title": "Fix the pricing table" },
    "project": { "id": "01J2...", "key": "WEB", "name": "Website" },
    "reason": "waiting_on_human",
    "trigger_at": "2026-07-12T00:00:00.000Z"
  }
]
```

`issue` and `project` are full objects, abbreviated here; `project` is `null` for a standalone
issue. `reason` is `waiting_on_human` or `new_activity`.

### POST /inbox/:issue_id/mark-read

Marks an inbox item read and returns `{"ok": true}`.

## Events

### GET /events

Streams HQ changes as [server-sent events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events).
**Also under `/mobile/v1`**, which streams the same events. Clients use it to know when to refetch
cached data.

```bash
curl -N http://127.0.0.1:9300/events \
  -H "Authorization: Bearer $DASH_TOKEN"
```

Each event's name is its `type`, and its data is the JSON event:

```text
event: agent:config-changed
data: {"type":"agent:config-changed","agent":"assistant","fields":["model"]}

: keepalive
```

A `: keepalive` comment is sent every 30 seconds.

| `type` | Fields |
|--------|--------|
| `agent:config-changed` | `agent` (name), `fields` (`["*"]` on create, `["removed"]` on delete) |
| `channel:created` | `channel` |
| `channel:config-changed` | `channel`, `fields` |
| `channel:removed` | `channel` |
| `channel:restarted` | `channel`, `reason` |
| `conversation:changed` | `conversationId`, `revision` |
| `conversation:deleted` | `conversationId`, `revision` |
| `mcp:server-added` | `server` |
| `mcp:server-removed` | `server` |
| `plugin:config-changed` | `plugin`, `fields` |
| `plugin:installed` | `plugin` |
| `plugin:removed` | `plugin` |
| `plugin:reloaded` | none |
| `swarm:run-changed` | `agentId`, `runId` |

Ignore event types you don't recognize.

### GET /agents/:agentId/conversations/:conversationId/events

Replays a conversation's durable chat events after a sequence number, so a client can catch up
after a dropped WebSocket without resending the prompt. **Also under `/mobile/v1`.** Errors use
the structured shape.

| Query | Description |
|-------|-------------|
| `sinceSeq` | Optional non-negative integer. Default `0`. Returns entries with a higher sequence |

```json
{
  "entries": [
    {
      "seq": 42,
      "msgId": "00000000-0000-4000-8000-000000000002",
      "agentId": "3f9c2a1b",
      "conversationId": "018f0f4a-...",
      "timestamp": "2026-07-12T00:00:00.000Z",
      "payload": { "type": "event", "event": { "type": "text_delta", "text": "Hi" } }
    }
  ]
}
```

A deleted conversation returns `{"entries": []}`. Any query parameter other than a single
`sinceSeq` returns `400 validation_failed`. An unknown agent, or a conversation that belongs to a
different agent, returns `404 not_found`. See [HQ Chat WebSocket](/api-hq-chat-websocket) for the
event payloads and how to resume a turn.

## Conversations and chat

Conversations, messages, and chat are documented on their own pages:

- [HQ Mobile API](/api-hq-mobile) covers conversation lists, messages, titles, deletion, and
  `POST /mobile/v1/ws-ticket`. The conversation routes are also available unprefixed on this
  loopback API with the management bearer.
- [HQ Chat WebSocket](/api-hq-chat-websocket) covers `/ws/chat`: sending messages, resumable
  turns, answers, cancellation, voice mode, and browser live view.

<Note>
  The loopback management API on port `9300` and the channel server on port `9200` use separate
  management and chat credentials. Native clients never receive the management bearer: the pinned
  mobile listener and the relay accept only the mobile bearer, on `/mobile/v1` and `/ws/chat`.
</Note>
